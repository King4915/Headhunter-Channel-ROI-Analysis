分维度明细

仅统计猎头渠道。点击表头可排序，Δ 为费用变化率；对比期落在数据范围外时为空。

指标口径

单入职成本 = 费用 / 入职人数；到岗周期 = 空岗天数合计 / 入职人数；保期留存率 = 1 − 6 个月保期内流失 / 入职人数。以上各项均只取猎头渠道记录。

空岗成本与 ROI

空岗成本 = 空岗天数 × 日薪 × 1.35（含团队产出折损系数），日薪 = 年薪 / 365。ROI 倍数 = 空岗成本 / 猎头费用，≥1 表示填补该岗位减少的损失已覆盖猎头支出。

对比规则

同比 YoY 自动回退 12 个月（季 / 年粒度按对应档数回退）；环比 MoM 回退上一期；自定义可任选对比区间。对比期落在数据范围外时显示为空。

部署到 GitHub Pages
1. 把 猎头渠道ROI看板.html 放到仓库根目录，可命名为 index.html；
2. 仓库 Settings → Pages → Source 选 main 分支根目录，几分钟后得到 https://用户名.github.io/仓库名/；
3. 打开页面点「数据源 / Supabase」，填入 URL 与 anon key 并连接，配置会保存在该浏览器。

Supabase 准备
1. 新建项目后，在 SQL Editor 执行「下载建表 SQL」得到的脚本（含两张表与 RLS 策略）；
2. anon key 是公开密钥，安全性由 RLS 控制；内部使用建议在 Dashboard 打开邮箱登录，并把 RLS 策略收紧到指定账号；
3. 表名固定为 hh_suppliers 与 hh_hires，改动表结构需同步改页面。
